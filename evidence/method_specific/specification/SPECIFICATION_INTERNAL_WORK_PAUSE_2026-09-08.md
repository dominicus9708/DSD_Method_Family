## Future reinforcement policy

DSD Specification should be reopened later when meaningful **external real-world cases** become available.

Preferred future evidence includes:

```text
NEW_EXTERNAL_CASE_WITH_NEW_BOUNDARY
REAL_WORLD_REQUIREMENT_CHANGE_OR_MAINTENANCE_CASE
RESOLUTION_WITHHELD_EXTERNAL_CASE
EXTERNAL_CASE_ALLOWING_PROSPECTIVE_PRECOMMIT
GENUINE_INDEPENDENT_EVALUATOR_RESULT
FROZEN_HUMAN_MEASUREMENT_RESULT
```

External reinforcement should prioritize cases that expose a new boundary rather than merely increasing favorable counts.

Cases with failure, partial match, mixed result, or `NO_GAIN` remain valid and should be preserved without repair.

Strong conventional baselines should continue to be used where comparison is appropriate.

## Reopening discipline

When DSD Specification work resumes:

1. Continue from Protocol v1.0 and the existing evidence ledger.
2. Precommit claims and scoring before outcome reveal where feasible.
3. Preserve source authority and external validation standards.
4. Record negative, partial, mixed, and blocked outcomes.
5. Do not reopen Protocol v1.0 or the shared core merely because a new case is difficult.
6. Reopen semantics only if a concrete external case demonstrates an actual semantic defect or missing stable obligation.
