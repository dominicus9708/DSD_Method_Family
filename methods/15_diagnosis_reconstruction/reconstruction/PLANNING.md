## 1. Goal

Develop Reconstruction / DSD 복원론 as an independent DSD method for determining which prior, omitted, damaged, compressed, or otherwise hidden structures and histories remain compatible with available evidence.

Reconstruction is not allowed to silently become:

~~~text

Lineage
Diagnosis
Aggregation
Compression
Transformation
Measurement
Comparison
Audit
historical truth by default
global uniqueness by default
~~~

## 4. Working five-interface identity — not yet frozen

~~~text
INPUTS:
  declared reconstruction question
  declared prior/omitted/damaged/compressed source class
  available evidence and provenance
  frozen forward/reduction/transition maps when relevant
  typed status/support/provenance sidecars
  collision/kernel/injectivity records when available
  Tracking / Lineage handoffs when supplied
  temporal/history/regime/resolution scope
  relational/cross-coordinate conditions when relevant

OPERATION:
  evaluate every declared source/history candidate
  against frozen evidence and forward/interface semantics;
  preserve unavailable, conflicting, ambiguous,
  information-lost, and unresolved states;
  retain all compatible candidates;
  identify exclusions and blocked evaluations;
  record provably unrecoverable distinctions;
  evaluate uniqueness only within the frozen class/scope;
  emit additional-evidence/sidecar handoffs

OUTPUTS:
  reconstruction candidate register
  evidence-to-source compatibility ledger
  admissible reconstruction set
  excluded reconstruction set
  blocked / unresolved records
  collision / equivalence-class ledger
  unrecoverable-information record
  uniqueness-scope record
  provenance / trace / lineage handoff ledger
  additional-evidence handoff
  maximum-supported claim

FAILURE_OR_NO_GAIN_CRITERIA:
  post-hoc source-class change
  unsupported global-uniqueness promotion
  reconstruction from noninjective output without retained multiplicity
  witness-history -> actual-history conflation
  reconstructed link -> established trace/lineage promotion
  missing required interface -> negative evidence conflation
  coordinatewise -> relational/full-source overpromotion
  incompatible typed status/support/provenance collapse
  fair baseline match -> NO_GAIN when appropriate

VALIDATION_STANDARD:
  protocol conformance
  prospective precommit
  direct positive/negative/boundary/NO_GAIN cases
  deterministic retrace
  frozen-axis audit
  later external/independent evidence kept separate
~~~

## 6. Initial boundary-pressure priorities

The first boundary attack should explicitly include at least:

~~~text
B1
  equal aggregate / equal reduced readout
  with distinct source supports

B2
  injective on declared class
  but noninjective globally

B3
  coordinatewise recoverable
  but relational coupling unrecoverable

B4
  formation witness-history available
  but no temporal-history license

B5
  missing Tracking link
  with several admissible reconstructed links

B6
  reconstructed link compatible
  but Lineage identity not established

B7
  relation-valued transition with multiple predecessors

B8
  definitional Property recompletion
  vs evidence-based unknown-source reconstruction

B9
  required reconstruction sidecar unavailable
  vs known destructive information loss

B10
  one remaining declared reconstruction
  while candidate-class completeness is not established

B11
  no candidate in the declared class
  without proving no real past state exists

B12
  current hidden-state Diagnosis result
  that does not determine past history

B13
  branch / merge history with no unique chain

B14
  conflict between trace evidence and reconstruction-compatible candidate

B15
  same numerical value / label / class
  without source identity

B16
  additional-evidence handoff
  without silently executing Measurement/Optimization

B17
  competent non-DSD inverse-problem procedure
  that reaches the same bounded result

B18
  strongest-reasonable comparator pressure
  reserved for later precommitted challenge design
~~~

The boundary attack may reorganize these cases before protocol freeze.
